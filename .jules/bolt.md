## 2026-03-29 - String indexing & pre-computed tokens for fuzzy matching
**Learning:** In list filtering operations across hundreds or thousands of items, repeatedly lowercasing search queries, evaluating regexes inside character match loops, and scanning character-by-character causes substantial overhead (~16.8ms per filter call). Replacing character-by-character scan loops with `String.prototype.indexOf()` fast jumps, replacing inline regex boundary tests with `charCodeAt()` range checks, and pre-computing lowercased query tokens reduces fuzzy search latency by over 6x (~2.7ms per call) with identical scores and match results.
**Action:** Always pre-compute search query token variants outside item filtering loops, and use `indexOf` or character-code range checks instead of inline regexes inside hot inner search loops.
